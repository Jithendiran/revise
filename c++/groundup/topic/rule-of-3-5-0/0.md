# Rule of Zero
The Rule of Five describes what to do when a class manages a raw resource directly. The Rule of Zero describes how to avoid that situation entirely.

> **If a class uses only well-managed member types, define none of the five special functions. The compiler-generated versions will be correct.**

Well-managed types — `std::string`, `std::vector`, `std::unique_ptr` — already implement all five special functions correctly. When a class uses only these as members, the compiler-generated functions delegate correctly to each member's own implementation:

```cpp
class Document {
    std::string  title;     // manages its own heap buffer
    std::string  content;   // manages its own heap buffer
    int          pageCount;

public:
    Document(std::string t, std::string c, int p)
        : title(std::move(t)), content(std::move(c)), pageCount(p)
    {}

    // No destructor        — std::string destructors release their buffers
    // No copy constructor  — std::string copy constructors deep copy
    // No copy assignment   — std::string copy assignment deep copies
    // No move constructor  — std::string move constructors transfer ownership
    // No move assignment   — std::string move assignment transfers ownership

    // All five compiler-generated versions are correct
};
```

**The Rule of Zero in practice:**

```cpp
Document a("Title", "Content", 5);
Document b = a;               // deep copy — std::string handles it
Document c = std::move(a);    // move — std::string transfers its buffers
b = c;                         // copy assignment — correct
b = std::move(c);              // move assignment — correct
```

All five operations work correctly with zero user-defined special functions.

**When the Rule of Zero is not possible:**

When a class must own a raw resource directly (wrapping a C API, implementing a custom allocator, or building a container from scratch), the Rule of Five applies and all five must be user-defined. In modern C++, `std::unique_ptr` wraps raw ownership with correct move-only semantics, enabling the Rule of Zero even for single-ownership heap resources:

```cpp
class DataBuffer {
    std::unique_ptr<int[]> data;   // unique_ptr manages the heap block
    int                    size;

public:
    DataBuffer(int n) : size(n), data(std::make_unique<int[]>(n)) {}

    // No destructor — unique_ptr deletes the array
    // No copy — unique_ptr is move-only (copy constructor deleted)
    // Move constructor and assignment — generated correctly from unique_ptr's move
    // This is the Rule of Zero
};
```
