## Lambda

### Why Lambda Functions Were Introduced
Before lambda functions existed, if a program needed to perform a quick, one-time task (like filtering a list of numbers or sorting data), a separate function had to be written completely outside the main block of code.

This created two distinct problems:
* Separation of Logic: The code that used the function and the function itself were written in different places. This forced anyone reading the code to scroll up and down the file constantly to understand a single operation.
* Code Pollution: The program became crowded with many small, single-use functions that were never needed anywhere else.

### What Problem Do They Solve?
Lambda functions solve these problems by allowing inline functions. A lambda function is an anonymous function (a function without a name) created exactly at the spot where it is needed.

By using a lambda function, code remains localized (written completely in one place) and clean, avoiding the need to create permanent, named functions for temporary tasks.

Lambda function idea is taken from operator `()` overloading

```cpp
class Multiplier {
    double factor;
public:
    Multiplier(double f) : factor(f) {}

    double operator()(double value) const {
        return value * factor;
    }
};

Multiplier triple(3.0);
triple(5.0);    // calls operator()(5.0) → 15.0
```

This works. But using it requires:
- A named struct or class
- A constructor to capture the context
- A data member to store it
- The `operator()` definition
- The whole thing defined far from where it is used

When the logic is simple and used in one place, all of this overhead is disproportionate. A sort comparator, a filter predicate, a transformation function — these are tiny pieces of logic that should be expressible inline, at the point of use.

**A lambda is the compiler doing all of that automatically.**

When the compiler encounters a lambda expression, it generates an anonymous class with:
- A data member for each captured variable
- A constructor that initializes those members from the captured values
- An `operator()` containing the lambda body

```cpp
// What the programmer writes:
double factor = 3.0;
auto triple = [factor](double value) {
    return value * factor;
};

// What the compiler generates (approximately):
class __lambda_1 {
    double factor;             // captured variable becomes member
public:
    __lambda_1(double f) : factor(f) {}  // constructor captures it

    double operator()(double value) const {  // body becomes operator()
        return value * factor;
    }
};

__lambda_1 triple(factor);   // lambda expression constructs the object
```

Every rule about lambdas follows directly from this transformation:
- Captures become data members — value captures are copies, reference captures are references
- `mutable` lifts the `const` from `operator()` — allowing captured copies to be modified
- The closure object has a size equal to the sum of its captured members
- The closure type is unique and unnamed — only `auto` can store it directly

Understanding `operator()` and functors first makes every lambda rule predictable rather than arbitrary.

### Closure

In C++ (and programming in general), a closure is the runtime object created by a lambda expression.

To understand it clearly, it helps to distinguish between the blueprint and the actual entity:
* The Closure Type: The unique, anonymous class generated by the compiler behind the scenes (e.g., __lambda_1).
* The Closure Object (The Closure): The actual object instantiated in memory when the lambda expression is evaluated at runtime (e.g., triple).

> What Makes Up a Closure?
> A closure bundles two things together into a single package:
> * The Code: The executable instructions defined inside the lambda's body (the equivalent of operator()).
> * The Environment: The state captured from the surrounding scope (the variables captured by value or reference, stored as data members).

Here, triple is the closure. When the compiler runs this line, it constructs an object of the anonymous class, initializes its internal data member with factor = 3.0, and stores it in triple.

#### Key Characteristics of a Closure
* Stateful: Because it holds captured variables as data members, a closure remembers state between function calls (if mutable or capturing by reference).
* Unique Type: Every lambda expression generates a distinct, compiler-generated class type that no other part of the code knows the name of, which is why must use auto to store it.
* Size: Its memory size is equal to the sum of all the variables it has captured.

### Syntax Anatomy
```
[ capture_clause ] ( parameters ) -> return_type { body }
```
1. Capture Clause ([]): Specifies which variables from the surrounding local scope are available inside the lambda, and how they are passed (by value or by reference).
2. Parameter List (()): Defines the input arguments, exactly like a standard function. This can be omitted if no parameters are taken.
3. Return Type Arrow (-> type): Specifies the type of data returned. This is optional; the compiler can automatically deduce the return type in most scenarios.
4. Function Body ({}): Contains the actual code to be executed.


### simple lambda

```cpp
#include <iostream>

// A function that accepts a function pointer taking no arguments and returning nothing
void executeAction(void (*action)()) {
    action(); // Invoking the passed closure
}


int main() {
    // Syntax for variable to store function pointer as well as lambda: return_type (*pointer_name)(parameter_types)
    int (*addNumbers)(int, int) = [](int a, int b) -> int {
        return a + b; // The '-> int' explicitly forces an integer return type
    };

    int result = addNumbers(10, 20);
    std::cout << "Result: " << result << "\n"; // Outputs: Result: 30

    // The lambda closure is created and passed directly inside the argument list
    executeAction([]() {
        std::cout << "Closure with no parameters executed smoothly.\n";
    });
}
```

### Lambda Capture Modes and Mechanics
The square brackets [] at the beginning of a lambda expression form the capture clause. This clause determines how variables from the enclosing local scope are made available inside the lambda's body. There are two primary mechanisms for capturing variables: by value (making a copy) and by reference (linking to the original memory).

1. Specific Captures (Explicit List)
    Explicit captures nominate specific variables individually. This gives precise control over what the lambda can access and how.
    * `[x]` Capture Specific Variable by Value: Creates a distinct copy of `x` inside the lambda when the lambda is defined. The value is a snapshot; changes to the original `x` outside the lambda after its definition will not affect the copy inside. By default, this copy is read-only (const) inside the lambda.
    * `[&x]` Capture Specific Variable by Reference: Creates a reference to the original variable `x`. No copy is made. If the lambda modifies `x`, the original variable changes. If the original variable changes outside, the lambda sees the updated value.
    ```cpp
    #include <iostream>

    int main() {
        int x = 10;
        int y = 20;

        // x is copied (by value), y is linked (by reference)
        auto lambda = [x, &y]() {
            // variable captured at the time of creation, x is copy so it is 10, y is reference address is copied value can change any time so it is 30 not 20
            std::cout << "Inside X = " << x << std::endl;   // y = 10
            std::cout << "Inside Y = " << y << std::endl;   // y = 30
            // x = 50; // ERROR: x is read-only by default
            y = 50;    // VALID: changes the original y outside
        };
        
        x = 20; // changing x value before calling it will not reflect
        y = 30; // changing y value before calling it will reflect
        lambda();
        std::cout << "Outside X = " << x << std::endl;  // x = 20
        std::cout << "Outside Y = " << y << std::endl;  // y = 50
    }
    ```
2. Default Captures (Implicit Catch-All)
    When a lambda needs access to many variables, or the specific variables are not fixed, a default capture mode can be used. The compiler scans the lambda body and automatically captures any referenced local variable according to the specified rule.
    * `[=]` Default Capture by Value: Any local variable used inside the lambda body is automatically copied by value.
    * `[&]` Default Capture by Reference: Any local variable used inside the lambda body is automatically captured by reference.
    ```cpp
    int main() {
        int a = 1;
        int b = 2;

        auto valLambda = [=]() {
            int sum = a + b; // a and b are automatically copied by value
        };

        auto refLambda = [&]() {
            a = 10; // a and b are automatically captured by reference
            b = 20; 
        };
    }
    ```
3. Mixed/Hybrid Captures
   Default captures can be combined with specific overrides to fine-tune access rules. The default rule must always be placed first.
   * `[=, &x]` Capture all by value, except `x` by reference: All accessed variables are copied, but `x` is linked by reference.
   * `[&, x]` Capture all by reference, except `x` by value: All accessed variables are linked by reference, but `x` is copied.
    ```cpp
    int main() {
        int a = 1, b = 2, c = 3;

        // Everything by value, but 'c' by reference
        auto hybrid1 = [=, &c]() {
            int sum = a + b; // Read-only copies
            c = 30;          // Modifies original 'c'
        };
    }
    ```
4. Capturing Objects and Object State (`this` and `*this`)
    When writing a lambda inside a member function of a class, the lambda does not automatically see the member variables of that class because they belong to the object instance, not the local stack frame. To access them, the object itself must be captured.
    1. `[this]` (Capture Object Pointer by Value)
        Captures the hidden this pointer by value. This grants the lambda direct read/write access to all member variables of the enclosing class.
        * Underlying Mechanics: Even though the pointer is copied by value, it still points to the exact same object in memory. Therefore, modifying a member variable inside the lambda alters the original object immediately.
    2. `[*this]` (Capture Object by Value)
        Copies the entire object instance into the lambda.
        * Underlying Mechanics: The lambda gets its own completely independent copy of the object. Changes to member variables inside the lambda only affect the copy stored within the lambda, leaving the original object unchanged. This is vital for asynchronous or multi-threaded programming where the original object might go out of scope and be destroyed before the lambda runs.
    
    ```cpp
    class Player {
        int health = 100;

    public:
        void setupHandlers() {
            // Accesses the object via pointer. 
            // CRITICAL: If the Player object is destroyed, calling this lambda crashes.
            auto referenceInstance = [this]() {
                health = 0; // Modifies original object member
            };

            // Deep-copies the entire object state.
            // SAFE: If the original Player object is destroyed, this lambda remains safe to run.
            auto copyInstance = [*this]() {
                // health = 0; // Modifies only the internal copy (requires 'mutable' to write)
            };
        }
    };
    ```
### The dangling pointer risk:
```cpp
#include <functional>
#include <iostream>

class BankAccount {
    double balance;
public:
    BankAccount(double b) : balance(b) {}

    std::function<void()> getReporter() {
        return [this]() {
            std::cout << balance << "\n";  // accesses this->balance
        };
    }
};

int main() {
    std::function<void()> report;

    {
        BankAccount acc(1000.0);
        report = acc.getReporter();  // lambda captures 'this' = &acc
    }   // acc destroyed here — this inside the lambda now points to freed stack memory

    report();   // UNDEFINED BEHAVIOR: reads balance from destroyed object
                // may print garbage, may crash, may appear to work
}
```
**The fix — capture *this by value**
```cpp
std::function<void()> getReporter() {
    return [*this]() {           // copies the entire BankAccount object
        std::cout << balance << "\n";   // reads from the copy, not the original
    };
}
```
